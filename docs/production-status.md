## M1 출시 차단

- 빌드 두 가지
  - `npm run build`: 테스트 주소(Pages)·e2e용. `?dev=1`(전투 전부 열기, 부모 문 0.2초), `?speed=`, `?voice=off`, `window.__hd`가 동작한다.
  - `npm run build:release`: 스토어·앱용. 위 옵션을 읽는 코드 자체가 번들에서 빠지고, `scripts/check-release.mjs`가 남았는지 검사해 남으면 빌드를 실패시킨다.
- `npm run e2e:release`: 출시 빌드를 브라우저로 열어 `?dev=1&speed=8&voice=off`가 먹지 않는지 확인 (`__hd` 없음, 2단계부터 잠김).
- 안드로이드 워크플로는 출시 빌드를 써야 한다 → **`deploy/android-apk.yml`을 `.github/workflows/android-apk.yml`에 덮어 커밋해야 적용된다** (바뀐 줄은 `npm run build` → `npm run build:release` 하나).
- 저장
  - 전투 구성(`STAGE_SET`)이 바뀌어도 깬 기록을 지우지 않는다. `STAGE_STEPS`(구성 n → n+1 표)로 옮긴다. 대응이 애매하면 앞 단계로 붙인다.
    - stageSet 없는 옛 저장: s1, s2만 유지 (4단계·6단계 옛 구성 모두 s1=수박, s2=쉬운 단어)
    - 구성 2(6단계) → 3: s1→s1, s2→s2, s3→s2, s4→s3, s5→s4, s6→s5 (다 깼으면 6단계부터)
    - 더 새 구성(옛 앱으로 되돌린 기기)은 대응을 몰라 전투 진행만 처음부터
  - 옮기기 전 원본은 `inwoo-hangul-robot.save.v2.before-stageset3`에 처음 한 번 보관하고, 옮긴 결과는 바로 저장해 다음 실행부터 다시 옮기지 않는다.
  - 단어 기록·설정은 어느 경우에도 유지. 옮겼거나 저장이 실패하면 부모 화면 '기록' 문단에 한 줄로 알린다.
  - 전투 구성을 바꿀 때: `STAGE_SET`을 올리고 `STAGE_STEPS`에 한 칸 추가. 빠지면 `tests/progress.test.ts`가 실패한다.

## M2 전투 개선

- 로봇 (관절): 어깨→팔꿈치 두 마디 팔 양쪽, 다리 분리. 충전(무릎 굽힘·흙먼지·추진기 깜빡임) → 무장 전개(팔 들며 굽힌 팔꿈치를 뻗고 포신·냉각 날개 전개, 왼팔 버팀) → 발사 반동(포신 밀림·팔꿈치 살짝·무릎 눌림·탄피) → 복귀. 피격: 몸통 비틀림·무릎 꺾임·불꽃. 방어: 왼팔을 앞으로 올림.
- 마법소녀 (다른 연출, 같은 단계 수): 충전은 몸이 떠오르고 빛 알갱이가 솟음(로봇의 웅크림과 반대) → 마법봉 한 바퀴 돌려 겨눔 → 휘어 날아가는 별빛 탄 → 치마·포니테일 펄럭임. 필살은 두 팔을 들어 올림. 피격·방어 자세 따로.
- 명중 흐름 한 곳(`landHit`): 효과음·히트 스톱(35/70/130ms, 게임 반복 시계 기준)·명중 별·말풍선(쾅!/펑!/콰광!, 팡!/반짝!/샤랑!, 차례로 고름)·폭발·적 피격(고개 젖힘)·시간차 작은 폭발 두 번.
- 콤보마다 공격 자체가 다르다: 1 대포 한 발 / 2 대포+손목 광선총 / 3 대포·손목·대포 / 4 미사일+대포 / 5 미사일 두 번 엇갈려 / 6 필살(배경 어두워짐·광선이 적을 뚫고 화면 끝까지) / 직접 쓴 최고 필살. 마법소녀: 1 별빛 탄 / 2 마법진 둘 3연사 / 3 마법진 셋 5연사 / 4 유성 넷 / 5 유성 여섯 / 6 거대 광선.
- 공격 시작→첫 명중 약 0.7초 (연출을 늘린 뒤 1.2초까지 늘어 다시 줄였다: 단어 완성 뒤 바로 시원하게).
- 적: 일반(공룡, 물기)·무리(작은 괴물, 통통 뛰고 같이 뜀·침 쏘기)·돌진(뿔공룡, 뒤로 젖혀 발 구르고 속도선 돌진)·장갑(새 갑옷 공룡: 낮고 넓은 등딱지·곤봉 꼬리, 꼬리로 땅을 쳐 충격파)·보스(쿵 뛰어 내려찍고 불덩이). 대기 동작도 종류마다 다르다.
- 갑옷 공룡: 8단계(방패 1)에 처음 나와 무료 10단계에서 적 다섯 종류를 모두 본다. 11단계 이후 규칙에서 방패 두른 뿔공룡 자리를 갑옷 공룡이 맡는다. 균형표는 종류가 빠지면 컴파일 오류가 나게 바꿨다(전에는 형 변환으로 숨어 실행 중 멈출 수 있었다).
- 디자인 체계: `:root`에 선·버튼색·테두리·모서리·그림자 토큰. 부모 화면의 기본 컨트롤(체크 상자·슬라이더·선택)을 게임과 같은 스위치·노란 손잡이·두꺼운 테두리로. 작은 버튼도 눌리는 그림자. 타이틀의 출격 버튼을 캐릭터 그림 위에 띄우지 않고 아래 판에 붙임, 비활성은 반투명 대신 흐린 단색.
- 전투 연출은 모두 전투 영역 안(장면 카메라)에서만 그려져 조합판을 가리지 않는다. 효과음과 단어 음성의 겹침 정리는 M5.
- 스크린샷: `docs/screens/before/`, `docs/screens/after/` (같은 이름끼리 비교). 연출 연속 장면은 `docs/screens/after/sheet-*.png`.
- 도구: `node e2e/showcase.mjs <폴더> [robot|magicalGirl|foes|ui]` — Phaser 반복을 멈추고 한 프레임씩 넘기며(벽시계도 가짜로) 67ms 간격으로 찍는다. `node e2e/sheet.mjs <폴더> <접두사> <출력.png>`로 한 장에 모은다.

## M3 무한 진행

- `stageAt(n)`: 1~10은 손으로 만든 무료 구간, 11부터 `generateStage(n, seed)`. 같은 번호·시드면 늘 같은 전투(시드 = 설정 시드 × 생성기 판 × 번호). `GEN.version`을 올리면 같은 번호의 내용이 바뀐다(깬 기록은 번호로 남아 그대로).
- 난이도 상한: `GEN.capAt = 61`. 그 뒤로 함정 수·어려움 비율·단어 길이·콤보 여유·연출 크기·적 수가 오르지 않는다. 보스 체력도 상한(대형 12, 중간 9).
- 5의 배수 = 중간 보스(대장 뿔공룡), 10의 배수 = 대형 보스(거대 공룡, 약해지면 직접 쓰는 필살기). 보스는 둘째 무리로 나온다.
- 단어 초점(긴 단어·받침·쌍자음/ㅐ)은 번호로 돌리고, 권장 어휘를 끈 설정에서도 단어가 8개 이상 되게 넓힌다.
- 지역: 10단계마다 새 지역(화산섬·얼음 골짜기·구름 성·깊은 바다·모래 유적·별빛 우주·버섯 숲·번개 산, 다 쓰면 "화산섬 2"…). 지역마다 전투 배경 색과 '새 지역 발견' 그림이 다르다.
- 진행: 앞에서부터 이어서 깬 다음 단계(frontier)로 출격, 1단계로 돌아가지 않는다. 지도는 지역 두 개씩 ◀ ▶로 넘긴다. 승리 화면은 늘 '다음 전투'.
- 저장: 깬 기록 목록 상한을 1000 → 100000으로 (M1 마이그레이션 때 둔 1000이면 1000단계 넘는 기록이 잘렸다).
- 검증 단계 1·10·11·15·16·100·1000·10000을 테스트로 만든다: 재현성, 보스 주기, 상한, 연령팩별 단어 수, 지역 이름, 이상한 번호 거부.

## M4 결제

- 경로 확인 (공식 저장소 문서, 2026-09-29): `capacitor-plugin-cdv-purchase` 13.18.0 = cordova-plugin-purchase v13의 Capacitor판(MIT). `@capacitor/core ^6 || ^7 || ^8` 지원(13.15.2부터 Capacitor 7·8), Android는 Google Play Billing Library 9.0.0(13.17.0부터)으로 빌드, 매니페스트에 BILLING 권한을 스스로 넣는다(minSdk 23). 이 프로젝트는 @capacitor/core 7.6.9.
- 상품: `hangul_all_stages` (비소모성). 1~10단계 무료, 사면 11단계부터 전부. **Play Console에 같은 ID로 인앱 상품을 만들어야 한다.**
- `src/core/purchase.ts` `PurchaseService`: unknown → locked → purchasing → (pending) → owned. 결제 대기는 열지 않는다. approved를 받으면 `finish()`(Play 확인 처리 acknowledge)를 거래당 한 번만 부르고, 실패하면 권한을 주지 않고 다시 올 때 재시도. 취소·실패는 잠김으로. 복원. 순서가 뒤섞여 와도 산 것을 되돌리지 않는다.
- 권한은 학습 기록과 다른 키(`hangul-daejakjeon.entitlement.v1`)에 저장: 진행 초기화·기록 손상이 구매를 지우지 않고, 오프라인에서도 산 단계를 한다.
- `src/services/billing.ts`: 앱(네이티브) = `PlayBilling`(플러그인은 앱에서만 불러오는 별도 조각), 웹 = `NoBilling`(결제 없음 → 모든 단계 열림, 웹 시험판 안내), 개발 빌드 `?billing=fake` = 테스트 더블. 출시 빌드에서는 `?billing=` 읽기가 빠지고 검사도 한다. 영수증 검증 서버는 쓰지 않아 기기 정보를 밖으로 보내지 않는다.
- 보호자 확인: 두 자리 곱셈 답을 숫자판으로 입력(보기 없음), 틀리면 새 문제. 결제 창은 이것을 통과해야만 열린다. 부모 화면(길게 누르기) 안에서도 구매는 같은 확인을 거친다.
- 화면: 10단계 뒤 '새 지역 발견' → 구매 안내(가격·설명·구매·복원·나중에). 지도의 11단계 이후는 금색 자물쇠, 누르면 구매 안내. 부모 화면 설정 맨 위에 '구매' 칸(상태·안내·복원).
- 스크린샷: `docs/screens/after/390-buy-01-offer.png`(안내), `-02-gate`(보호자 확인), `-03-owned`, `-04-pending`.

### 검증 (2026-09-29)

## 막힌 것 (BLOCKED)
- `.github/workflows/` 변경은 사용자가 직접 커밋해야 함: `deploy/android-apk.yml`
- 실제 결제 시험 (M4): Play Console에 앱 등록 → 인앱 상품 `hangul_all_stages`(비소모성) 생성·가격 설정 → 내부 테스트 트랙에 서명된 AAB 업로드 → 라이선스 테스터 계정으로 구매·결제 대기(느린 테스트 카드)·환불·복원 확인. 에뮬레이터·웹에서는 결제가 되지 않는다. 가격은 사용자가 정해야 한다(화면은 스토어가 알려 준 가격을 그대로 보여 준다).
- iOS 결제: 같은 플러그인이 StoreKit 2를 지원하지만 App Store Connect 상품 등록과 기기 시험이 필요하다.
